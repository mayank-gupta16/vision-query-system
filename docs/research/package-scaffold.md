  This is not a reservation. No publishing is configured or performed.

## Scope

Only help/version behavior, reproducible developer commands, four CI lanes, and
packaging/supply-chain validation. No media runtime, domain records, database,
server, model adapter, or inference benchmark is included.

The [developer guide](../testing/development.md) records commands and trust
boundaries. The [development inventory](../legal/development-tool-inventory.json)
is separate from runtime-only CycloneDX generated by each fresh wheel check.
Frozen issue #3 research remains unchanged.

## Validation record

The [raw CPU-LITE receipt](scaffold-cpu-lite-receipt.json) records 19 exact input
hashes, hardware, working directories, seven successful command groups, raw
output, wall/CPU time, peak RSS, artifact hashes, runtime SBOM and allocated disk.
It identifies an issue #8 working snapshot on the accepted toolchain base;
the explicit hashes, not an uncommitted-HEAD claim, identify measured inputs.

On the disposable Ubuntu 26.04.1 x86_64 VM (4 vCPU, Intel Skylake virtual CPU,
15 GiB visible RAM, 8 GiB swap), a fresh Python 3.13.15 tool directory measured:

| Operation | Wall seconds | Peak RSS KiB |
| --- | ---: | ---: |
| uv plus managed Python bootstrap | 1.88 | 47,520 |
| Wrapper lock check plus editable all-groups sync | 1.05 | 72,856 |
| Offline checks, 80 tests, coverage, licenses, repository policy | 3.19 | 90,324 |
| sdist, wheel, fresh runtime, bad backend-hash rejection | 0.83 | 49,912 |
| Public dependency audit | 1.59 | 60,420 |

Allocated footprint after build and before audit, measured separately: uv
49,908 KiB; managed Python 110,856 KiB; development environment 115,596 KiB;
cache 117,024 KiB; build outputs 32 KiB. Another fresh runtime-only install
occupied 164 KiB excluding the interpreter. Hardlinks can be counted in multiple
trees: these values must not be added as unique disk consumption.

Compared with the frozen research receipt's direct editable sync of 0.62 s /
70,712 KiB, the application wrapper sync is 1.05 s / 72,856 KiB. The wrapper also
starts host Python, checks toolchain receipts, and checks the lock; package
metadata and network/cache conditions differ. These single-run observations are
not a statistical regression or throughput benchmark. GNU time precision is
0.01 s, and filesystem/network caches outside the fresh task directory are
uncontrolled.

The hashed public-package audit reported **no known vulnerabilities on
2026-09-06** on both the Mac reference environment and the fresh CPU-LITE run.
The audit emits warnings that `--no-deps` is redundant with `--require-hashes`;
it still uses fully hashed input and succeeds. This is point-in-time advisory
evidence, not a vulnerability-free guarantee.

GitHub CI adds fresh `ubuntu-24.04` x86_64 and `macos-15` arm64 jobs for Python
3.13.15/3.14.7 with a stable aggregate gate. Final CI run URLs and independent
final-commit reviews are recorded in the linked PR before merge. Host runner
patch levels can drift; these labels are not immutable VM images.

## Remaining limitations

No software release or registry upload was performed. Managed Python, bundled
development tools/data, and missing upstream notices do not receive redistribution
approval from this issue. Windows/other architectures, hostile media isolation,
model execution, schemas, persistence, and query behavior remain outside scope.
