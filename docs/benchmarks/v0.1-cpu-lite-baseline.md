## Pinned workload and boundary

The [versioned fixture manifest](../../fixtures/v01-benchmark/manifest.json)
defines a virtual 60-second, 1920×1080 RGB24 source. It creates 1,800 exact-PTS
30-FPS candidate records, samples 300 frames at exactly 5 FPS in 29 bounded
pages, and performs a byte-preserving 1280×720 crop and SHA-256 operation for
every selected frame. It then commits the 300 frame records and 300 evidence
records through the preparing, artifact-intent, staged-promotion, ten batched
metadata-transaction, and finalization path. The harness reopens both local
stores, verifies their integrity, retrieves the artifact, and traverses both
indexes with bounded pagination.

The deterministic RGB24 frame is generated in memory and reused. Identical
crops intentionally deduplicate to one 2,764,800-byte artifact while all 300
crop/hash operations and evidence references still execute. No encoded media is
materialized, decoded, or retained. No model, external dataset, inference,
accuracy evaluation, network capability, person, face, plate, or personal data
is involved. This measures the released fake/manual v0.1 application boundary;
it is not a real-video decoding or perception-performance claim.

One crop and 64 sampling candidates warm the implementation and are excluded
from the timed total. Input generation is reported separately and is also
excluded. The total begins with bounded exact-PTS sampling and ends after the
reopened indexed queries. Stage timings are single-run diagnostic observations;
they are not additive because the total also includes orchestration between
stages.

## Reproduce and compare

Use the reference managed interpreter and an existing private work directory:

```sh
revision=$(git rev-parse HEAD)
PYTHONPATH=src artifacts/toolchain/3.13.15/python/\
cpython-3.13.15-linux-x86_64-gnu/bin/python3 \
  scripts/run_v01_benchmark.py \
  --work-root /private/visualworld-validation \
  --output /private/visualworld-validation/v0.1-candidate.json \
  --revision "$revision"

PYTHONPATH=src artifacts/toolchain/3.13.15/python/\
cpython-3.13.15-linux-x86_64-gnu/bin/python3 \
  scripts/compare_v01_benchmarks.py \
  --baseline docs/benchmarks/v0.1-cpu-lite-baseline.json \
  --candidate /private/visualworld-validation/v0.1-candidate.json \
  --output /private/visualworld-validation/v0.1-comparison.json
```

The comparator fails closed on malformed, non-regular, incompatible, failed, or
over-limit receipts. Compatibility binds the exact fixture/configuration,
CPU-LITE machine requirements, CPython/SQLite versions, and manifest hash while
allowing the source revision to change. Its initial noisy single-run guardrail
allows at most a 20% regression in wall time, CPU time, FPS, real-time factor,
peak RSS, or logical store size; the 2 GiB RSS release ceiling always applies.
Negative regression values represent improvements. A failure requires
investigation and an explicit disposition; it is not evidence of model-quality
change because this workload makes no accuracy claim.
