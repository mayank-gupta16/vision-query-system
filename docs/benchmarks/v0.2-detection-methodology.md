# v0.2 detector/runtime research methodology

Issue [#21](https://github.com/mayank-gupta16/vision-query-system/issues/21)
compares a deliberately short same-family detector list on CPU-LITE. The
decision is evaluation-only: it may select the adapter direction for v0.2, but
does not add a root dependency, weights, media, or a public model-backed API.
The measured outcome is published separately in the
[detector/runtime results](v0.2-detection-results.md).

## Locked candidates

The candidate list uses the three Apache-2.0 Open Model Zoo MobileNetV2-SSD
vehicle detectors at the immutable Open Model Zoo revision
`86ba23e80b27eb9149da911e5c023b108cb06e80`. They share architecture, output
contract, FP32 OpenVINO IR format, and runtime; input resolution is the main
independent variable.

| Candidate | Input | OMZ internal AP 0.50:0.95 | GFLOPs | Model bytes |
| --- | ---: | ---: | ---: | ---: |
| `vehicle-detection-0200` | 256 x 256 | 0.254 | 0.786 | 7,454,391 |
| `vehicle-detection-0201` | 384 x 384 | 0.322 | 1.768 | 7,454,582 |
| `vehicle-detection-0202` | 512 x 512 | 0.363 | 3.143 | 7,454,662 |

The upstream specifications are pinned with the source revision in the
[`0200`](https://github.com/openvinotoolkit/open_model_zoo/blob/86ba23e80b27eb9149da911e5c023b108cb06e80/models/intel/vehicle-detection-0200/README.md),
[`0201`](https://github.com/openvinotoolkit/open_model_zoo/blob/86ba23e80b27eb9149da911e5c023b108cb06e80/models/intel/vehicle-detection-0201/README.md),
and
[`0202`](https://github.com/openvinotoolkit/open_model_zoo/blob/86ba23e80b27eb9149da911e5c023b108cb06e80/models/intel/vehicle-detection-0202/README.md)
model pages. [`candidates.json`](../../fixtures/v02-detection-research/candidates.json)
locks each XML/BIN URL, byte size, download SHA-384, local SHA-256, runtime
wheel, source revision, configuration grid, and preprocessing policy.

The common runtime is the official OpenVINO 2026.3.1 CPython 3.13 Linux wheel,
NumPy 2.5.3, and OpenVINO Telemetry 2025.2.0, installed from exact local wheels
without dependency resolution or network access. Every inference worker uses
only the CPU device, one stream, four inference threads, the latency hint,
OpenVINO linear resize, and RGB-to-BGR conversion.

## Locked dataset

The dataset contains 20 deterministic 640 x 360 RGB24 PPM frames derived from
ten distinct CC0 Wikimedia Commons vehicle photographs. Four source photographs
produce the eight calibration items; six different photographs produce the 12
test items. A source never crosses the split. Each source produces one `easy`
and one `small_distant` scene, with exactly one annotated vehicle.

[`source-manifest.json`](../../fixtures/v02-detection-research/source-manifest.json)
records page and file revisions, artist, CC0 terms, immutable thumbnail URL,
download hash and dimensions, half-open object crop, plate redactions, and a
human privacy review. The generator replaces every selected plate with a solid
neutral patch, tightly crops the vehicle, applies fixed-point bilinear resizing,
and composites it onto a project-generated road scene containing no person,
face, plate, text, or imported asset. The generated frames therefore contain
no real people or retained personal data. Binary sources and derivatives remain
ignored and are never committed.

[`annotations.json`](../../fixtures/v02-detection-research/annotations.json)
locks every derived frame SHA-256, item ID, split, stratum, dimensions, and one
ground-truth box. The gate-compatible
[`dataset-manifest.json`](../../fixtures/v02-detection-research/dataset-manifest.json)
binds the source manifest, separate split annotation hashes, item-ID hashes,
rights, privacy classification, and stratum counts.

The source JPEG decode is a one-frame RGB24 operation in bubblewrap with no
network, one read-only input, and one private temporary output. The measured
Ubuntu FFmpeg and bubblewrap package versions and executable hashes are locked.
That host decoder is an acquisition tool, not a distributed project component.

## Calibration and test protocol

The frozen [`v0.2-gates-1`](v0.2-evaluation-gates.md) protocol controls the
seed set, one warmup pass, five measured repetitions, CPU-LITE profile, required
strata, integer units, and absolute gates. Each candidate is calibrated without
opening test predictions:

1. Retain ranked vehicle predictions down to confidence `0.01`.
2. Evaluate the frozen confidence grid from `0.05` through `0.95` on all five
   calibration repetitions.
3. Keep configurations passing every calibration precision and recall floor.
4. Select the highest overall F1; break ties by higher small/distant recall and
   then the higher threshold.
5. Freeze that candidate-specific threshold before measuring the test split.

Precision and recall greedily match at most one detection to the single
ground-truth object at IoU >= 0.50. Remaining detections are false positives.
`map50_basis_points` is COCO-style class AP at IoU 0.50: detections are ranked
globally by confidence, matched one-to-one, precision is monotonically
interpolated, and its values at 101 recall thresholds from zero through one are
averaged. The dataset has one evaluated class, `vehicle`; each frame contributes
at most its top 100 detections. AP considers every retained prediction down to
`0.01`; the calibrated threshold applies only to operating-point precision and
recall. Higher-is-better ratios round down and lower-is-better milliseconds
round up.

Steady-state FPS includes OpenVINO preprocessing, inference, and output
validation after locked PPM loading. One generated frame represents 0.2 source
seconds, so real-time factor is FPS divided by five. Cold start runs from worker
initialization through imports, model read/compile, and the first inference.
Warm start is the first timed inference after one complete untimed dataset pass.
Peak RSS is the maximum worker `ru_maxrss`; CPU time and multi-core utilization
are retained as diagnostics. CPU nanoseconds per frame divide summed process
user-plus-system time by the 12 test items; frames per CPU-second is its inverse.
Install/model bytes are the logical installed environment plus the selected XML
and BIN.

## Reproduction boundary

Acquire only the exact source and wheel URLs recorded in the manifests, give
the source files their recorded `download_name`, and verify their SHA-256 before
use. Then run:

```sh
python3 scripts/prepare_v02_detection_dataset.py \
  --source-root artifacts/issue21/selected-sources \
  --output artifacts/issue21/dataset-v1

uv venv --python 3.13.15 --clear artifacts/issue21/venv
uv pip install --python artifacts/issue21/venv/bin/python \
  --offline --no-deps artifacts/issue21/wheels/*.whl

python3 scripts/run_v02_detection_benchmark.py \
  --dataset-root artifacts/issue21/dataset-v1 \
  --models-root artifacts/issue21/models \
  --runtime-python artifacts/issue21/venv/bin/python \
  --venv-root artifacts/issue21/venv \
  --wheels-root artifacts/issue21/wheels \
  --source-revision HASH_OF_REVIEWED_HARNESS_COMMIT \
  --evaluated-on 2026-09-07 \
  --output artifacts/issue21/results
```

Both tools refuse an existing output root. The benchmark verifies dataset,
annotation, model, and wheel locks; checks the exact Python/OpenVINO versions;
runs workers inside a read-only, network-unshared bubblewrap; emits raw
per-item predictions/timings and gate receipts; and immediately validates each
receipt through the frozen evaluator. The raw results retain no image pixels.

## Interpretation limits

This small, deliberately controlled vehicle-only set answers the reversible
v0.2 adapter/runtime question. It does not estimate broad traffic-scene,
pedestrian, bicycle, weather, camera-domain, demographic, or production-video
accuracy. Synthetic composition reduces background complexity, and several
sources depict the same vehicle brand. A passing result is sufficient to begin
the downstream v0.2 sampling/crop/tracking research; it is not a general model
quality claim or final shipping approval.
