# v0.2 original-resolution crop benchmark results

Issue [#23](https://github.com/mayank-gupta16/vision-query-system/issues/23)
finds material value in original-resolution retrieval for tiny source-resolvable
detail. The bounded recommendation is to preserve source coordinates and fetch
the original crop on demand when a downstream detail task justifies it. Do not
eagerly retain every source crop: median evidence is 56.25 times larger than the
detector-input crop. Retain only a justified selected best frame through the
existing evidence boundary.

## Decision

Every frozen absolute gate passes: mapping error is zero, source crops match the
direct byte oracle exactly, repetition failures are zero, median crop wall time
rounds to 2 ms, and worst peak RSS is 861,851,648 bytes (821.93 MiB).

On the paired combined metric, original pixels improve tiny readable detail by
1,601 basis points, exceeding the preregistered 500-basis-point materiality
threshold. Small improves 416 basis points and medium does not improve. The
combined specialist gain is 278 basis points for tiny, below its separate
1,000-basis-point threshold; materiality is established by the readable-detail
metric, not by specialist accuracy.

The source-absent control has exactly zero original-minus-detector gain for both
metrics overall and in every size. Original pixels therefore do not manufacture
recoverable signal when the source lacks it. Escalation is justified only when
quality/provenance indicates source-resolvable detail and a downstream task
needs it; medium objects and source-absent content do not justify escalation in
this boundary.

## Measured detail quality

Values are deterministic test accuracy in basis points. `Combined gain` gives
the preregistered metric across one resolvable and one absent panel per item.
`Resolvable gain` isolates the condition in which the source actually contains
fine detail.

| --- | ---: | ---: | ---: |
| Overall | 7,575 / 6,902 | +673 | +1,346 |
| Tiny | 7,638 / 6,037 | **+1,601** | +3,204 |
| Small | 7,547 / 7,131 | +416 | +834 |
| Medium | 7,539 / 7,539 | 0 | 0 |

| Size | Specialist original / detector | Combined gain | Resolvable gain |
| --- | ---: | ---: | ---: |
| Overall | 5,648 / 5,555 | +93 | +186 |
| Tiny | 5,833 / 5,555 | +278 | +556 |
| Small | 5,277 / 5,277 | 0 | 0 |
| Medium | 5,833 / 5,833 | 0 | 0 |

For resolvable panels, source crops recover 10,000 basis points on both metrics
in every size. Detector crops recover 6,796 / 9,444 readable/specialist basis
points for tiny, 9,166 / 10,000 for small, and 10,000 / 10,000 for medium. The
absent panel's absolute original and detector scores are identical by size; its
chance-like task accuracy is not interpreted as semantic evidence.

## Resource and storage observations

The source crop is 777,600 packed RGB24 bytes at the median versus 13,824 bytes
for the detector crop, a 56.25x ratio. Across the five test repetitions, the
median of per-repetition crop medians is 1.529 ms wall / 1.524 ms CPU for the
source path and 0.033 ms wall / 0.030 ms CPU for the detector path. These are
single-process Python measurements on raw in-memory frames, not decode or
durable-store latency.

| Observation | Result |
| --- | ---: |
| Mapping error, all strata | 0 pixels |
| Exact source-crop byte match, all strata | 100% |
| Median source crop | 777,600 bytes |
| Median detector crop | 13,824 bytes |
| Source / detector byte ratio | 56.25x |
| Frozen crop-wall gate value | 2 ms |
| Worst peak RSS | 861,851,648 bytes |
| Repetition failures | 0 |

Because 56.25x is above the frozen 4x threshold, an implementation should keep
the source reference and exact geometry, retrieve source pixels transiently,
and persist an original crop only when best-frame selection and a declared
specialist purpose warrant the cost. No production adapter changes in this PR.

## Limits and next boundary

The recommendation is limited to the frozen synthetic chart proxy, six test
sources, raw RGB24, exact boxes, and the selected detector geometry. It says
that source sampling preserves spatial information; it does not establish real
OCR or attribute-model accuracy and must not be read as permission for face
identity or unrestricted crop retention. A future adapter must enforce purpose,
retention, and EvidenceStore custody while preserving the source coordinate and
provenance contracts. Issue #24 remains the next v0.2 research dependency.
