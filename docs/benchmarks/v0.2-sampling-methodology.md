# v0.2 frame-sampling research methodology

Issue [#22](https://github.com/mayank-gupta16/vision-query-system/issues/22)
measures fixed and bounded-adaptive frame sampling against moving-object event
recall on CPU-LITE. It uses the detector selected by issue #21 and produces a
reversible evaluation recommendation. It does not add a model, runtime, media
asset, or production sampling adapter to the package.

## Question and hypothesis

The question is how far VisualWorld can reduce decoded/detected frames without
losing vehicle events or the repeated observations needed to start a track.
The preregistered hypothesis is that a 3 FPS base policy with short motion
bursts up to 8 FPS will retain the frozen event-recall floors with fewer samples
than fixed 8 FPS. Fixed 1, 2, 3, 5, and 8 FPS provide the comparison curve.

[`candidates.json`](../../fixtures/v02-sampling-research/candidates.json) locks
those policies, a 750 ms adaptive burst, and the calibration-only motion grid
`0.03`, `0.05`, `0.07`, and `0.09`. Motion is the maximum 32 x 24 tile mean
absolute RGB delta, sampled every fourth pixel and represented as integer
millionths of 255. The adaptive policy uses the 3 FPS nearest-PTS schedule
outside a triggered window and replaces it with the 8 FPS schedule inside the
window. It therefore never stacks both schedules during a burst.

Every policy uses `vehicle-detection-0201` with OpenVINO 2026.3.1 at the frozen
`0.95` confidence threshold selected by issue #21. The detector candidate
manifest SHA-256 is
`38afb812c6681700c15b30874e91ac649f1dde521354a5ce5c27d1b4e7bafcee`.

## Locked dataset and rights

The dataset is ten deterministic six-second, 384 x 216 RGB24 rawvideo MOV
clips: four calibration clips and six source-disjoint test clips. Each contains
86 frames with a 1/1000 time base. The cadence repeats 67, 67, and 66 ms, except
frame 70 is extended by 266 ms to create an explicit VFR gap while preserving a
six-second duration. Every clip has one event in each required stratum:

- `small_fast`: a small vehicle crosses rapidly;
- `camera_motion`: the background moves while the vehicle is partially
  occluded;
- `cut_adjacent`: a vehicle appears immediately after a hard cut;
- `vfr_gap`: a moving vehicle spans the enlarged presentation-time gap.

The 40 annotated events and all 860 frame PTS values, durations, object boxes,
event memberships, and RGB24 hashes are locked in
[`annotations.json`](../../fixtures/v02-sampling-research/annotations.json).
[`dataset-manifest.json`](../../fixtures/v02-sampling-research/dataset-manifest.json)
binds source-separated split hashes, event-ID hashes, stratum counts, and the
rights/privacy declaration. The
[`source manifest`](../../fixtures/v02-sampling-research/source-manifest.json),
SHA-256
`5de7f5c08709bcb98c0b056d85203bce7fbb3bbf85563f397b9536067178402c`,
accepts only the plate-sanitized CC0 derivatives locked by issue #21. The
generator crops those vehicles, resizes them with fixed-point bilinear
interpolation, and places them on project-generated backgrounds. The generated
clips contain no person, face, plate, retained personal data, text, font, or
unrecorded imported asset.

Source PPMs, generated MOVs, model weights, runtime wheels, extracted runtimes,
and inspection images remain ignored and are never committed. Only manifests,
annotations, aggregate evidence, and pixel-free prediction metadata may enter
Git. The dataset is approved solely for evaluation and is not a product or
release payload.

## Calibration, measurement, and metrics

The adaptive threshold is chosen on the calibration split without opening test
results. Each threshold receives one untimed warmup and five measured
repetitions using the frozen seeds. Thresholds whose aggregate passes all
accuracy floors are ordered by lower median sample count and then lower numeric
threshold. If none passes, the experiment stops without measuring the test
split.

After calibration, every fixed policy and the selected adaptive policy receives
one untimed warmup and five measured test repetitions with seeds `1729`, `3253`,
`5081`, `7919`, and `104729`. Each inference worker runs the issue #21 exact
CPython/OpenVINO/NumPy closure inside a clear-environment, no-network,
read-only bubblewrap. Generated selected frames live in a private temporary
directory and are removed after the repetition.

A vehicle event is recalled when at least one selected frame inside its event
has a class-matched detector box at IoU >= 0.50. A missed-track opportunity is
an event with fewer than two such selected true positives. The frozen absolute
floors are:

| Metric | Overall | Small/fast | Camera motion | Cut-adjacent | VFR gap |
| --- | ---: | ---: | ---: | ---: | ---: |
| Event recall, minimum | 95% | 90% | 90% | 95% | 95% |
| Missed-track opportunity, maximum | 5% | 10% | 10% | 5% | 5% |

The harness also records samples and stored RGB bytes per source minute,
end-to-end real-time factor, peak RSS, parent/worker CPU time, decode plus motion
wall time, detector process wall time, and per-clip motion diagnostics. Accuracy
ratios round down; lower-is-better ratios round up where the gate contract
requires it. Gate metrics use the median of five repetitions except peak RSS,
which uses the worst observation; median absolute deviation is retained.

Sampling targets are defined on the presentation timeline and resolve to the
nearest frame PTS, with earlier frame index as the deterministic tie-break.
Selection never rewrites timestamps. Median and maximum nearest-frame error are
reported separately as diagnostics and are not treated as source time.

## Decision rule

Only candidates passing every frozen test gate are eligible. Choose the lowest
median samples per source minute, then lower detector CPU time, then fixed over
adaptive if still tied. The result can recommend a default and bounded override
triggers for later adapter design, but cannot approve model/runtime distribution
or silently change the existing public `PtsFrameSampler` contract.

## Reproduction boundary

Regenerate the clips from the exact issue #21 derived PPM directory, then run
the committed harness from an exact reviewed commit:

```sh
python3 scripts/prepare_v02_sampling_dataset.py \
  --input-root artifacts/issue21/dataset-boundaryfix-2 \
  --output artifacts/issue22/dataset-v3

python3 scripts/run_v02_sampling_benchmark.py \
  --dataset-root artifacts/issue22/dataset-v3 \
  --models-root artifacts/issue21/models \
  --base-python artifacts/toolchain/3.13.15/python/\
cpython-3.13.15-linux-x86_64-gnu/bin/python3.13 \
  --wheels-root artifacts/issue21/wheels \
  --source-revision HASH_OF_REVIEWED_HARNESS_COMMIT \
  --evaluated-on 2026-09-07 \
  --output artifacts/issue22/results
```

Both commands reject linked output components and existing output roots. Input
JSON rejects duplicate keys and non-finite numbers; identifiers and relative
paths fail closed. The benchmark verifies every clip and frame hash before
sampling, reconstructs the exact runtime from verified wheels, verifies model
hashes, emits content-addressed receipts and raw pixel-free evidence, and
immediately evaluates each receipt with the frozen v0.2 gate implementation.

## Interpretation limits

This is a deliberately small, vehicle-only, synthetic-motion dataset made from
ten source photographs. It covers declared speed, scale, occlusion, camera
motion, cuts, and VFR-gap risks, but does not estimate pedestrian, bicycle,
weather, compression, real-camera, dense-scene, long-video, demographic, or
production tracking performance. Motion calculation still decodes every frame;
the experiment compares downstream sample/detection cost and event retention,
not a decoder capable of skipping arbitrary compressed frames. A passing
result is an input to v0.2 adapter design and tracking research, not a V1
shipping claim.
