# v0.2 original-resolution crop research methodology

Issue [#23](https://github.com/mayank-gupta16/vision-query-system/issues/23)
measures whether an exactly mapped source-resolution crop preserves useful fine
detail that is lost in the detector input. It produces a reversible evidence
selection recommendation. It does not enable face identity, select an OCR/VLM,
retain sensitive crops, or add a production adapter.

## Question and comparison

The question is how much a 3840 x 2160 RGB24 source crop improves readable
detail after a vehicle has been localized in a 384 x 384 detector input. Both
paths use the same locked detector-space box, so detector recall and
localization cannot confound the comparison:

- `original-source-rgb24` maps the box through the production
  `DetectorTransform` and extracts a byte-preserving packed source crop;
- `detector-input-rgb24` crops the already resized detector frame.

No detector runs in this experiment. The geometry matches the selected
`vehicle-detection-0201` baseline: linear RGB24 resize to 384 x 384 without
letterboxing, with the detector candidate manifest bound by SHA-256.

## Locked dataset and rights

The dataset is ten deterministic three-frame 3840 x 2160 rawvideo MOV clips:
four calibration clips and six source-disjoint test clips. Each clip contains
one tiny, small, and medium vehicle frame. The vehicle pixels derive only from
the ten plate-sanitized CC0 frames approved by issue #21; backgrounds and detail
charts are project-generated. Every clip, frame, detector crop, source crop,
box, label, source relationship, and split is digest-locked.

Each vehicle carries two panels. The source-resolvable panel contains a frozen
binary chart. The source-absent control is constant gray before either resize,
so an apparent improvement there would invalidate the result. The chart has
three adjacent 8 x 8 task regions:

- `face_visibility` represents coarse visibility only, never identity;
- `plate_ocr` uses non-identifying project-generated labels, never a real plate;
- `vehicle_detail` uses project-generated detail labels.

Eight deterministic codewords exist per task. No real face, plate, identifier,
text, font, biometric data, or personal data enters the generated clips. The
source manifest records CC0-1.0 rights, privacy facts, upstream annotation and
manifest hashes, and deterministic derivation. Generated MOVs, source images,
crops, and inspection images remain ignored. Only manifests, annotations, and
pixel-free aggregate/result metadata enter Git; the set is evaluation-only and
is not a product or release payload.

## Frozen reader, protocol, and metrics

The fixed reader samples the center of each of the 24 x 8 cells at luminance
threshold 127. Readable-detail accuracy is the fraction of 192 bits recovered.
Each task prediction is the codeword with minimum Hamming distance, with the
lowest numeric label as the tie-break. There is no learned specialist and no
parameter search.

The experiment follows the frozen `v0.2-gates-2` CPU-LITE contract: one untimed
warmup and five measured repetitions with seeds `1729`, `3253`, `5081`, `7919`,
and `104729`. Calibration is inspected before the sealed test split. Test gate
metrics use the median of the five repetitions, except peak RSS uses the worst
observation. Accuracy ratios round down and bounded latency rounds up.

The absolute gates require:

| Metric | Required value |
| --- | ---: |
| Source-box L-infinity mapping error | <= 1 source pixel |
| Exact source-crop byte match | 100% overall and per size |
| Crop wall latency | <= 1,000 ms |
| Peak RSS | <= 2 GiB |
| Repetition failure rate | 0% |

Diagnostics record original/detector crop bytes, wall and CPU time, readable
cells, exact task accuracy, paired gains by size, and separate results for the
source-resolvable and source-absent controls.

## Preregistered decision rule

The source-absent control must have no material recovery: the absolute
original-minus-detector readable and specialist gains must each be at most 500
basis points overall. Otherwise no recommendation is made.

Original retrieval is material when every absolute gate passes and at least one
required test stratum has either a specialist-accuracy gain of 1,000 basis
points or a readable-detail gain of 500 basis points. If median source evidence
is more than four times the detector crop, the recommendation must be transient
on-demand retrieval plus selective best-frame retention, not eager retention
of every original crop. If no material gain appears, detector-input evidence
remains sufficient inside the measured boundary and escalation requires both
source-resolvable detail and a downstream specialist need.

## Calibration-only amendment

The first locked fixture used detector-space panel footprints of 20 x 16, 40 x
24, and 80 x 48 pixels. Calibration had zero mapping error, 100% exact crop
matches, zero failures, and no source-absent gain. Tiny readable detail improved
821 basis points, but detector-input specialist accuracy was already 100% in
every size. The codewords were therefore too error-tolerant at those footprints
to discriminate the intended fine-detail boundary.

Before opening the test split, the public issue record amended only the panel
footprints to 8 x 8, 20 x 16, and 40 x 24 detector pixels for tiny, small, and
medium. Sources, splits, dimensions, paired controls, charts, tasks, threshold,
metrics, seeds, gates, and materiality rules did not change. The dataset was
regenerated twice and compared byte-for-byte before the amended calibration.

  --dataset-root artifacts/issue23/dataset-v5 \

cpython-3.13.15-linux-x86_64-gnu/bin/python3.13 \
  --source-revision d9b4bdc305051a2e8cd91a17bc4b90115551ed03 \
  --evaluated-on 2026-09-07 \

Both tools reject linked or existing output roots. Inputs are bounded regular
files; JSON rejects duplicate keys and non-finite values; nested candidate and
derivation semantics, identifiers, paths, split/source bindings, sizes, and
digests fail closed. The benchmark verifies every MOV and frame before use,
binds the CPython and geometry closure, emits content-addressed receipts and
pixel-free raw evidence, and immediately evaluates the receipt with the frozen
gate implementation.

## Interpretation limits

This is a small vehicle-only chart proxy with ten CC0-derived source objects,
six test sources, three exact boxes per source, synthetic backgrounds, raw RGB
video, and one detector preprocessing geometry. It does not estimate real OCR,
face analysis, recognition, model confidence, compression, blur, weather,
night, dense-scene, pedestrian, bicycle, demographic, or production-camera
performance. Chart accuracy shows retained spatial signal, not semantic model
quality. Memory includes the harness's in-process raw 4K buffers and is not a
production storage claim. The result can guide evidence retrieval design but
cannot approve sensitive inference or eager pixel retention.
